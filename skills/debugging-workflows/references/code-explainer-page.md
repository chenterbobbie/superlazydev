# Code explainer page

Use this outline for a standalone explanation requested by the user. Adapt the language to the intended reader and omit sections that do not apply.

## Page outline

1. **What happened** — describe the user-visible symptom and expected behavior.
2. **Where the behavior lives** — link to the relevant entry point and modules using verified repository paths and symbols.
3. **How it works** — follow the important control flow and data/state changes in order.
4. **Why it failed** — explain the root cause with evidence from the code or reproduction.
5. **What changed** — describe the fix and any behavior it intentionally preserves.
6. **How it was checked** — list the actual commands or scenarios run and their results; identify unchecked cases.

Keep the explanation scoped to the affected path. Define project-specific terms, avoid unsupported claims, and do not paste large source blocks when a link and explanation are clearer. Write the page to a repository location only when the user requests a saved artifact and its destination is clear.
